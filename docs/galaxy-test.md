## 시험 범위

네이티브 APK는 실제 Azure API에 연결하는 모드와 오프라인 DEMO를 제공한다.
오프라인 제품 이슈 DEMO는 자체 제작한 에어컨·세탁기·냉장고·모니터 합성 패널을 사용한다.
기존 클라우드 시험은 별도 합성 리모컨을 사용한다. 삼성 실제품 지원을 뜻하지 않는다.
연결된 Galaxy가 없어 설치, 카메라, OCR, TTS와 정합은 아직 하드웨어에서 검증하지 못했다.
자동 테스트와 클라우드 확인 결과는 [검증 기록](./verification.md)을 참고한다.

## 준비와 설치

* Android 8.0(API 26) 이상이며 [ARCore 지원 목록](https://developers.google.com/ar/devices)에 있는 Galaxy
* Google Play Services for AR와 카메라 권한
* 타깃을 표시할 PC 또는 두 번째 화면
* 음성 안내를 시험할 경우 한국어 TTS 음성 데이터
* 클라우드 시험 시 인터넷과 운영자가 발급한 일회용 단말 코드

[0.2 사전 시험 디버그 APK](https://github.com/daeungo1/visual-product-recognition/releases/download/v0.2.0-photo-demo/app-android-debug.apk)를 설치한다.
[체크섬](https://github.com/daeungo1/visual-product-recognition/releases/download/v0.2.0-photo-demo/app-android-debug.apk.sha256)으로
다운로드 무결성을 확인할 수 있다. 로컬 빌드 결과는 Git에 포함하지 않는다.
패키지는 `kr.demo.visualguide`, 버전은 `0.2-demo`, 대상 SDK는 35다.
개발용 서명이며 스토어 배포용이 아니다.
main 미병합 개발 브랜치 빌드이며 기존 `latest`의 0.1과 구분한다.
Knox나 회사 설치 정책이 차단하면 관리자에게 승인받고 정책을 우회하지 않는다.

다운로드한 파일을 프로젝트 루트에 둔 경우, USB 디버깅이 허용된 기기는
다음 명령을 사용할 수 있다. 직접 빌드했다면 APK 경로를 빌드 출력으로 바꾼다.
여러 기기가 있으면 `-s`에 대상 시리얼을 명시한다.

```powershell
& '.\.tools\android-sdk\platform-tools\adb.exe' devices
& '.\.tools\android-sdk\platform-tools\adb.exe' install -r '.\app-android-debug.apk'
```

다른 개발 서명의 설치본은 덮어쓸 수 없다. 이때 앱을 삭제하면 단말 등록과
세션 복원 정보가 제거되므로 클라우드 시험에는 새 페어링이 필요하다.
운영자 코드는 8~256자이며 공개 문서나 APK에 포함하지 않는다.

## PC 타깃 준비

실모델 사진 참조 시험은 별도 모드다.
`에어컨·모니터 실모델 사진 참조 DEMO`에서 AF90H19D35WN 또는 LS32HG802SKXKR을 선택한다.
공식 사진 원본 페이지를 확인한 뒤 사용권 있는 로컬 JPEG/PNG를 불러온다.
사용권·정확한 모델을 직접 확인해야 안내 카드가 열린다.
모델 미확인, 사진·모델 변경과 초기화가 사진·확인·수동 보고를 지우는지 시험한다.
손상 파일·10 MiB 초과·20 MP 초과는 오류를 표시하고 진행하지 않아야 한다.
이는 카메라·자동 모델 인식·실제 고장 해결 시험이 아니다.
공식 사진은 재배포 허가가 확인되지 않아 APK에 내장하지 않았다.

[4종 제품 이슈 웹 목업](https://daeungo1.github.io/visual-product-recognition/)을 PC에서 연다.
Galaxy에서 `카메라로 제품 이슈 DEMO`를 선택하고 PC에 표시할 제품을 고른다.
카메라로 전체 타깃을 비추면 합성 제품 후보가 나타난다.
`이 제품 확인 · 증상 보기` → `이 증상 · Overlay 안내 시작`을 선택한다.
같은 타깃이 재탐지되면 버튼 하이라이트와 증상 안내 카드가 나타난다.
PC의 해당 영역을 누르고 앱에서 OCR 또는 수동 확인으로 진행한다.

세탁기의 DOOR CLOSED나 모니터 SIGNAL OK는 PC 가상 표시일 뿐,
실제 문 잠김·세탁 가동·영상 복구를 검증한 증거가 아니다.
실제 제품에 임의 좌표·버튼 조합·설정 숫자를 적용하지 않는다.
미등록 제품, 서로 다른 타깃 두 개, 가림과 앱 중지 시 안내가 차단되는지 확인한다.
카메라 미지원 시 `수동 제품 선택 (인식 성공 아님)`으로 시나리오를 살펴볼 수 있다.

아래는 기존 리모컨 및 클라우드 시험용 별도 타깃이다.
[기존 합성 리모컨](https://daeungo1.github.io/visual-product-recognition/demo-target.html)을 연다.
오프라인으로 시험하려면 [합성 리모컨 HTML](../assets/demo-target.html)을 내려받아 열고
같은 위치에 [기준 PNG](../assets/demo-target.png)를 둔다.
그림의 POWER, MODE, TEMP 영역을 누르면 표시 상태가 바뀐다.
인쇄한 PNG는 추적 전용이며 표시 상태를 바꿀 수 없다.
이전에 타깃을 열어 두었다면 브라우저를 새로 고침해 개선된 그림을 불러온다.

가이드는 `POWER ON`, `MODE COOL`, `TEMP 24` 순서다.
다시 시험할 때 HTML도 초기화한다. 이미 맞는 표시 상태를 인식하는 것은
새로 버튼을 누른 사실을 검증하는 것과 다르다.

PC 타깃의 실제 포인터 클릭, 상태 변경, 초기화와 좁은 화면 표시는 자동 검증했다.
아래 이미지는 시험할 PC 타깃이며 휴대폰 앱 화면이 아니다.

![실제 브라우저에서 검증한 합성 리모컨](./demo-target-preview.png)

## 실제 Azure 연결

1. 앱에서 `실제 HTTPS 클라우드 연결`을 선택한다.
2. API 원점이 아래 주소인지 확인한다.
3. 운영자의 일회용 코드를 입력하고 `페어링 · 연결`을 누른다.
4. `HTTPS 인증 카탈로그 연결됨`을 확인한다.
5. `에어컨`과 `리모컨`을 선택한다.
6. 카메라 권한을 허용하고 PC 타깃 전체를 비춘다.
7. `사진 1장씩 HTTPS 전송에 동의` 후 `사진 1장 · 실제 식별`을 누른다.
8. 반환된 DEMO 후보와 검색 점수를 확인한다. 점수는 식별 확률이 아니다.
9. `사용자 확인`으로 합성 가이드를 선택한다.
   가이드를 수동 선택했다면 식별 성공으로 집계하지 않는다.

현재 그림에 맞는 가이드 이름에는 `reference 0097d99781cc`가 표시된다.
가이드 ID는 `demo-aircon-0097d99781cc`다.
기존 참조를 덮어쓰지 않았으므로 옛 가이드도 남아 있다.
수동 선택할 때는 현재 그림에 해당하는 새 참조를 선택한다.

```text
https://ca-svg-dev-4ca0.whiterock-2d71d661.japaneast.azurecontainerapps.io
```

코드는 한 번만 사용할 수 있고 단말 토큰은 24시간 유효하다.
같은 코드를 재사용하지 않는다.
저장 단말의 암호화된 토큰은 해당 API 원점에만 전송한다.
만료 또는 안전 저장소 오류가 나면 등록을 삭제하고 새 코드로 다시 페어링한다.
비밀 코드를 스크린샷, 커밋, 티켓 또는 공개 로그에 올리지 않는다.

## 추적과 진행

1. 타깃 전체를 정면에 가깝게, 충분한 조명에서 비춘다.
   초기 탐지 때 화면의 25% 이상을 차지하도록 한다.
2. FULL_TRACKING 상태에서 현재 버튼에 안내가 붙는지 확인한다.
3. PC의 해당 버튼을 눌러 예상 표시 상태로 바꾼다.
4. OCR 자동 확인, `AI 확인 · 표시창 1장`, `수동 확인 · 서버 승인`을 각각 시험한다.
5. 자동 확인은 서버 응답이 도착한 뒤에만 완료되어야 한다.
   수동 완료는 OCR 또는 VLM 성공으로 집계하지 않는다.
6. `TEMP 124`처럼 목표와 다른 숫자는 `TEMP 24` 성공으로 처리하지 않아야 한다.
7. 가림, 카메라 이탈과 앱 백그라운드 이동 시 안내가 숨는지 확인한다.
8. 재탐지, 가로 회전, 카메라 권한 거절, 한국어 음성 미설치도 시험한다.
9. 네트워크를 끊고 진행이 성공으로 바뀌지 않는지 확인한다.
   보류 이벤트는 같은 UUID 재시도 기능으로 처리한다.
10. 앱 재시작 후 `저장 단말 · 세션 복원`과 `서버 단계 새로고침`으로
    서버의 현재 단계를 확인한다.

ARCore가 카메라를 단독 사용한다. 매 프레임 서버 전송은 하지 않는다.
식별 및 AI 확인은 명시적으로 누를 때만 최대 1024px, 2MiB JPEG 한 장을 보낸다.
표시창 crop은 원근 보정이 아닌 축 정렬 경계 상자다.
글자 기울기나 반사로 읽기 어려우면 자동 판정이 실패하거나 불확실할 수 있다.
fail, unsure, 타임아웃과 오류는 완료가 아니다.
OCR은 세 장 이상의 독립 관측이 0.8초 이상 안정되어야 요청되며
추적 상실이나 단계 변경은 대기 중 증거를 무효화한다.

## 오프라인 DEMO

사진을 전송하지 않는 제품 이슈 시험은 첫 화면의 `카메라로 제품 이슈 DEMO`를 선택한다.
기존 3단계 실습은 `기존 리모컨 · 오프라인 DEMO`를 선택한다.
같은 타깃으로 카메라 안내, 한국어 OCR, TTS와 수동 진행을 시험할 수 있다.
이 모드의 진행은 메모리 전용이며 화면 재생성 시 초기화될 수 있다.
실제 HTTPS 모드의 서버 영속성과 혼동하지 않는다.

## 기록과 실제품 전환

지원 Galaxy 모델, Android 버전, 조명, 거리, 추적 손실, 단계별 완료 출처와
소요 시간을 기록한다. 정합 오차는 버튼 기준점의 정답 라벨과 비교한다.
초심자 5명 이상의 시험 전에는 완주율을 보고하지 않는다.
[평가 러너](../eval/run_eval.py)는 측정 데이터로만 보고서를 만든다.

실제품으로 넘어가려면 가전 본체 및 리모컨 모델명, 호환 관계, 공식 절차,
사용 권한이 있는 기준 사진과 검수된 패널 지도가 필요하다.
현재 합성 타깃 좌표를 실제 삼성 제품 위에 재사용하지 않는다.
