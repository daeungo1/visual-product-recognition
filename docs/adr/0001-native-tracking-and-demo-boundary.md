## 상태

로컬 목업의 초기 선택이다. 실제품 추적 성능과 Azure 배포를 승인한 결정은 아니다.
사용자 부재 상태에서 원안과 일치하는 되돌릴 수 있는 코드 구성을 우선한다.

## 배경

카메라 안내의 핵심 지표는 식별, 버튼 정합과 사용자 완주다.
화면에 고정된 UI 요소를 그리는 웹 시안만으로 실제 카메라 정합을 검증할 수 없다.
현재 실제품 모델과 기준 사진은 제공되지 않았다.

## 결정

* Kotlin, Compose와 ARCore 기반 Android 목업을 만든다.
* 코어의 도메인과 단계 상태는 Kotlin 표준 기능으로 제한한다.
* 기기 및 클라우드 SDK는 바깥 어댑터에 둔다.
* 기준 이미지와 패널 지도를 제품별 버전 자산으로 관리한다.
* 움직이는 리모컨은 현재 카메라 영상으로 유효 추적 중일 때만 하이라이트한다.
* 최초 자산은 자체 제작한 데모 타깃으로 명명하고 앱에도 데모라고 표시한다.
* 실제품 자산이 없으면 미지원으로 표시하고 임의의 삼성 버튼 좌표를 사용하지 않는다.
* 수동 진행, OCR 확인과 서버 VLM 판정을 서로 다른 증거로 기록한다.

## 검토한 대안

모바일 웹은 화면 흐름 검토와 데모 타깃 표시에 사용한다.
네이티브 카메라 추적의 대체 검증으로 사용하지 않는다.

CameraX와 2D 특징점 정합은 저사양 및 ARCore 미지원 기기의 대안이다.
별도 정합 실험을 수행하기 전에는 자동 폴백으로 넣지 않는다.
유효하지 않은 추적을 정상처럼 보이는 고정 하이라이트로 대체하지 않는다.

일반 객체 검출기나 SAM 3를 매 프레임 서버에서 실행하는 경로는 초기 기준으로
사용하지 않는다. 마스크와 정확한 버튼 ID의 연결은 사람이 검수해야 하며,
네트워크 왕복이 매 프레임 안내의 필수 조건이 되어서는 안 된다.

## 결과와 재검토 조건

앱을 배포해도 지원하지 않는 실물에 안내가 뜨지 않을 수 있으며 이것은
지원 범위를 정직하게 제한한 결과다.
데모 완주를 실제품 평가 성공으로 집계할 수 없다.

실제 리모컨이 저특징점, 반사와 가림으로 수용 기준을 만족하지 못하면
ARCore와 2D 정합 또는 검출 및 추적 모델을 동일 촬영 세트에서 비교한다.
첫 구현의 도구 선택이 이후의 실측 결과보다 우선하지 않는다.
