## Intent

Build an accuracy-first vertical slice for Samsung Bespoke AI Combo
`WD80H25BHS`. A user selects a reviewed guide, photographs the appliance,
and receives independent Overlay results for the detergent dispenser and
control panel with actionable retake guidance.

## Verified inputs

The local source set contains three authorized product images and one Korean
manual. The uploaded manual filename mentions `SEW-650DW`, but its SHA-256
matches the manual downloaded from Samsung's official `WD80H25BHS` support
page.

* Product model: `WD80H25BHS`
* Product name: Bespoke AI Combo 25/18kg (71.1mm LCD + dial), dark steel
* Manual hash:
  `95E72378FAF9E9540D5FC047B8C76CB92C2E908AC0E5538B97A29A50054A1AC5`
* Official manual ID: `11813449`
* Official manual path:
  `OID139796_IB_WD80H-AD_28LCD_KO_260916.pdf`
* Product images: `bespoke1.png`, `bespoke2.png`, `bespoke3.png`

The registry identifies manuals by content hash, model applicability and
source metadata, never by local filename alone.

## Goals

* Resolve only the exact reviewed product and manual revision.
* Extract page text from the provided manual into reviewable local artifacts.
* Store component aliases, relative locations and source-page evidence.
* Accept multiple requested targets and return independent target outcomes.
* Preserve partial success when one target is located and another is not.
* Retry uncertain targets with bounded, original-image adaptive crops.
* Require two agreeing proposals before accepting generated geometry.
* Provide a concrete retake instruction when evidence is insufficient.
* Evaluate the three supplied images with repeatable target-level metrics.
* Expose the reviewed guide through the existing mobile browser demo.

## Non-goals

* P3 SAM 3.1 segmentation and GPU deployment.
* Continuous video tracking or Android ARCore.
* Supporting models other than `WD80H25BHS`.
* Global search across unreviewed manuals.
* Automatic publication of unreviewed extracted instructions.
* New image retention, deletion or privacy workflows.
* Using a generated answer when exact-product applicability fails.

Existing authentication, no-request-image-persistence behavior and protected
API routes remain unchanged. Accuracy work must not remove those controls.

## Architecture

```text
Mobile request
  -> exact product and guide selection
  -> reviewed registry applicability gate
  -> target normalization and alias resolution
  -> independent GPT region proposals per target
  -> two-of-three spatial consensus
  -> one bounded adaptive crop retry for uncertain targets
  -> crop coordinates remapped to root image
  -> target-level located, not_visible, uncertain result
  -> reviewed step text and actionable retake guidance
```

## Product registry

The API package stores reviewable JSON manifests under
`server/src/visual_guide/references/samsung/WD80H25BHS/`. Raw customer images
and PDF files remain excluded from Git.

`ProductManifest` records the canonical product ID, exact model codes, display
name and reviewed manuals. `ManualReference` records the official source URL,
content hash, language, revision and applicable model codes. Loading fails when
the content hash, exact model or review state does not match.

## Manual ingestion

The ingestion command reads a local PDF and writes deterministic UTF-8 text per
page plus a machine-readable extraction index. A pinned, workspace-local
Poppler CLI performs the one-time text extraction; PDF parsing is not added to
the API runtime. The command records source hash, page count and model-code
occurrences. Extraction does not make a manual reviewed.

A checked-in reviewed guide cites exact pages and short evidence snippets from
the extracted manual. The guide defines current state, target component,
instruction, expected state and verification mode.

## Multi-target contract

One request contains an exact product ID, guide ID, step ID and one or more
canonical target IDs. Each target returns its own status, geometry, evidence,
attempt count and optional retake instruction.

```text
located
not_visible
uncertain
```

`not_visible` means the target is outside the visible scene or occluded.
`uncertain` means candidates exist but cannot be uniquely grounded. Geometry is
present only for `located`.

## Adaptive crop

The first pass uses the whole transmitted image. Three independent proposals
are aggregated. When they do not produce two spatially agreeing candidates,
the server requests at most one crop retry for that target.

The crop planner uses the reviewed component's relative location as a bounded
prior. It crops pixels from the already decoded root image without upscaling.
All returned coordinates are deterministically mapped back to root-image
coordinates before validation.

## Evaluation

The evaluation uses all three supplied product images and the two initial
targets:

* `detergent_dispenser`
* `control_panel`

Human-reviewed root-image boxes are stored separately from raw images. The
report measures status accuracy, point-in-box, IoU, false `not_visible`,
partial success, proposal agreement, crop retry usage and latency.

The initial release criterion is no cross-product guide acceptance, successful
independent target results, and reproducible reports. Numeric quality gates are
set after the first labeled baseline rather than inferred from three catalog
images.

## Deployment

P0-P2 runs in the existing FastAPI Container App and uses GPT-6.1 Terra.
No GPU resource is required. P3 begins only after comparing the P0-P2 baseline
and finding a quota-capable Azure region for SAM.
