## 실행 범위

Kotlin, Compose, ARCore, ML Kit 및 FastAPI를 구현하고 실제 Azure 리소스를 배포했다.
사용자의 기능 우선 및 자율 진행 요청에 따라 구독, 지역, 비용과 위험을 제시하는
생성 및 배포 단계를 분리했다. 사용자가 부재한 질문 도구의 위임 응답에서는
원안에 맞는 선택으로 진행했으며 사용자가 직접 Yes를 입력했다고 기록하지 않는다.
실제품 자산과 Galaxy 하드웨어가 없는 범위는 현장 검증으로 남긴다.

## 현재 산출물 상태

네이티브 APK, 코어·Android 단위 테스트, API 및 평가 러너를 검증했다.
최신 개수와 실행 명령은 [검증 기록](./verification.md)에 날짜별로 구분한다.
기존 리모컨 참조는 공식 ARCore1.48 검사100점과 이미지 데이터베이스 생성을 통과했다.
추가한 제품형 합성 참조는 에어컨100, 세탁기90, 냉장고100, 모니터100점이다.
이는 SDK 품질 점수이지 실제 삼성 제품 인식률이나 Galaxy 정합 정확도가 아니다.
클라우드 API는 Cosmos, Blob, Search 및 실제 모델 어댑터를 사용한다.
Cosmos와 Blob의 공용 접근 차단을 유지하고 Private Endpoint와
VNet 통합 런타임으로 연결했다. 최종 실호출 상태는 검증 기록에 구분한다.
연결된 Galaxy와 실제 삼성 모델 자산은 없다.
[검증 기록](./verification.md)과 [실기기 테스트 절차](./galaxy-test.md)를 참고한다.

## 첫 번째 독립 산출물

갤럭시에 설치 가능한 Android 목업과 로컬에서 실행 가능한 가이드 API를 만든다.
공식 검수 자산이 없는 동안에는 자체 제작한 데모 타깃을 사용하며,
앱 안에서 데모임을 표시한다.
이 산출물의 목표는 카메라, 안내 흐름, 버튼 오버레이와 단계 진행을 실행하는 것이다.
삼성 제품 전체를 자동 식별하거나 실제 필터 장착을 보증하는 앱이 아니다.

2026-10-26의 직접 요구에 맞춰 제품 이슈 DEMO를 첫 진입점으로 추가했다.
PC 웹 목업과 APK는 에어컨·세탁기·냉장고·모니터의 독립 합성 패널을 공유한다.
웹 목업의 상태 비교는 실제 카메라·OCR·VLM 판정이 아니다.
새 네 패널은 오프라인·웹 전용이며 기존 클라우드 카탈로그에 게시하지 않았다.

## 컴포넌트와 경계

| 위치 | 책임 | 금지하는 의존성 또는 동작 |
|------|------|--------------------------|
| `core` | 도메인, 단계 상태 머신, 좌표와 추적 상태 규칙 | Android, ARCore, ML Kit, HTTP, Azure SDK |
| `app-android` | Compose UI, 카메라, ARCore, OCR, 음성, API 어댑터 | 승인되지 않은 모델을 실제품으로 표시 |
| `server` | 실제 이미지 식별, VLM 확인, 인증과 Cosmos 세션 | 실패한 의존성을 고정 후보 또는 성공 판정으로 대체 |
| `assets` | 명시적 데모 자산, 패널 좌표, 스크립트 | 임의의 삼성 모델명과 검증되지 않은 버튼 좌표 |
| `pipeline` | 자산 생성, 데모 타깃, 등록 데이터 검증 | 저작권 있는 영상의 무단 재배포 |
| `eval` | 재현 가능한 지표 계산 및 결과 구분 | 수동 확인을 자동 판정 성공에 포함 |

## 사용자 흐름

1. `카메라로 제품 이슈 DEMO`에서 카메라 권한을 허용하고 등록 합성 패널을 비춘다.
2. 현재 단일 타깃의 FULL_TRACKING이 잡히면 후보를 사용자가 확인한다.
   미등록·복수·추적 불확실 상태에서는 자동 확정하지 않는다.
3. 해당 제품 증상을 확인하고 `Overlay 안내 시작`을 누른다.
4. 선택 타깃이 현재 추적 중일 때 버튼 하이라이트와 카메라 위 증상 안내를 표시한다.
5. 안정 OCR 또는 명시적 수동 확인으로 진행하고 두 완료 출처를 구분한다.
6. 추적 상실·중지·제품 변경 시 이전 안내를 숨기고 증거를 무효화한다.
7. 실제 HTTPS 모드에서는 별도 단말 페어링·사진 전송 동의·사용자 후보 확인 후
   기존 등록 리모컨 가이드와 서버 승인 세션을 사용한다.

ARCore 설치 및 기기 지원, 카메라 권한 거부, 네트워크 실패와 OCR 미인식은
각각 이해할 수 있는 오류 상태로 표시한다.
데모 모드는 Azure가 없어도 안내 흐름을 시험할 수 있어야 한다.
실제품 자산 미등록과 AI 미설정 상태를 데모 결과로 대체하지 않는다.

## 작업 1 코어와 Android 목업

### 파일 및 인터페이스

* 생성: Gradle 프로젝트, `core/src/commonMain`, `core/src/commonTest`
* 생성: `app-android/src/main`, Android 매니페스트와 리소스
* 생성: `assets`의 자체 데모 타깃, 가이드, 패널 지도
* 입력: 단계 목록, 현재 단계 ID, 추적 상태, 타깃 좌표, OCR 관측
* 출력: 현재 단계, 완료 방식, 표시할 좌표 또는 숨김 상태

### 실행 체크리스트

- [x] 코어의 수동 진행, 완료 후 중복 진행 방지, 추적 상실, 숫자 OCR 경계를 테스트로 정의
- [x] 초기 생성한 상태 머신과 좌표 규칙을 JVM 테스트로 검증
- [x] Compose 선택 및 안내 화면과 카메라 권한 처리 연결
- [x] ARCore 추적 어댑터와 오버레이를 연결하고 마지막 자세 안내를 차단
- [x] OCR 및 음성 낭독을 붙이고 미지원 및 오류 상태 표시
- [x] 코어 JVM 테스트, APK 빌드와 Android lint 실행
- [ ] 실제 갤럭시에서 설치, 권한, 추적 및 OCR을 별도 확인

예상 검증 명령은 Gradle Wrapper가 생성된 뒤
`.\gradlew.bat :core:jvmTest :app-android:testDebugUnitTest :app-android:assembleDebug`다.
명령의 성공과 실제 갤럭시 검증 성공은 별개로 보고한다.

## 작업 2 로컬 가이드 API

### 파일 및 인터페이스

* 생성: `server/pyproject.toml`, FastAPI 진입점, 도메인 및 저장 어댑터
* 생성: `server/tests`의 API 및 상태 테스트
* 입력: 카테고리, 가이드 ID, 현재 단계 ID, 중복 방지용 이벤트 ID
* 출력: 버전이 있는 가이드와 세션 진행 결과, 명시적인 식별 불가 및 판정 불가

### 실행 체크리스트

- [x] 헬스 체크, 가이드 조회, 세션 생성과 이벤트 계약 테스트 작성
- [x] 미등록 모델, 잘못된 단계, 중복 이벤트와 AI 미설정의 실패 응답 정의
- [x] 생성한 최소 API의 동작을 테스트로 검증
- [x] 로컬 영속 저장을 사용하고 데모와 실제 AI 경로를 구분
- [x] 테스트와 린트를 실행하고 실제 HTTP 헬스 체크 확인
- [x] 로컬 실행 방법과 환경 변수 문서화
- [x] 실제 컨테이너, Azure 영속 저장 및 단말 인증 구현과 배포

Python 명령은 생성한 매니페스트의 개발 의존성을 기준으로
`uv run --project server pytest`와 `uv run --project server ruff check .`를 사용한다.
서버 기동 명령과 테스트 위치는 생성된 실제 진입점에 맞춰 문서화한다.

## 작업 3 Azure 연결 및 배포

확인된 CLI 기본 구독은 `ME-MngEnvMCAP359144-daeungo-1`
(`2cf925b6-80cb-4567-abda-5ccd3010aab5`)다.
실제 배포 지역은 Japan East다.
GPU 대신 실제 CPU 추론을 사용하며 원안의 SAM 3와 Content Understanding은 배포하지 않았다.
원격 모델 두 개를 실제 생성했고 GlobalStandard의 지역 처리 제한을 명시한다.

- [x] 앱 및 API의 빌드 상태와 실제 컨테이너 진입점 평가
- [x] 실제 모델 배포와 CPU SigLIP2 추론, Search와 지역 제약 확인
- [x] 별도 PoC 리소스 그룹, SKU 및 비용 범위를 제시
- [x] 별도 생성 단계 후 Bicep 및 컨테이너 설정 작성
- [x] 정적 검증과 실제 ARM what-if 확인
- [x] 별도 배포 단계 후 기본 서비스와 사설 네트워크 생성
- [x] 이미지 조회, 실제 식별/판정, 인증, Cosmos 세션과 재시작 영속성 검증
- [x] APK에 배포 HTTPS 주소 연결, 단말 어댑터 테스트와 빌드
- [ ] Galaxy 설치 및 카메라 기반 종단 간 검증

테스트 시간에는 API 및 식별 서비스를 예열한다.
APK에 Azure 비밀키를 넣지 않으며 관리 ID와 일회용 PoC 단말 인증을 사용한다.
이는 기업 사용자 SSO가 아니다.
리소스 생성만으로 이 작업이 완료된 것으로 처리하지 않는다.

## 작업 4 실제품 평가

모델별 공식 가이드와 본체·조작 패널·리모컨 사진이 확보되어야 시작한다.
사용자가 요청한 에어컨·세탁기·냉장고·모니터별로 우선 모델 하나와
공식 증상 절차 하나를 확보하고, 출처·적용 모델·사람 검수 후 등록한다.
첫 실증 순서는 확보 가능한 실제품과 승인된 절차에 따라 결정한다.
가상 TEMP 24/3, DOOR CLOSED, SIGNAL OK 등의 표시 일치는
실제 냉방·냉각·도어 안전·영상 복구의 성공 증거로 사용하지 않는다.
TV 다중 대상과 필터 관련 작업은 별도 자산·공식 절차·안전 검수 후 추가한다.

수용 기준과 측정 시 유의점은 [리서치 검토](./research-review.md)에 정의되어 있다.
원본 촬영, 정답 라벨, 자동 및 수동 진행 이벤트를 분리해서 보존한다.
초심자 5명 시험은 현장 검증이며 소프트웨어 자동 테스트로 대체하지 않는다.

## 완료 보고 원칙

각각 독립 상태로 보고한다.
