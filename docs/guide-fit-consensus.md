# 가이드 적합성 게이트와 다수결 (EgoAfford·VELA 참고 로직)

두 모듈은 `server/src/guide_api/`에 있으며 `core/src/commonMain`은 건드리지 않습니다. 참고 자료(VELA 랩)의 코드·사진·문서는 가져오지 않았고, 로직 아이디어만 이 저장소에서 새로 구현했습니다.

| 모듈 | 역할 |
|---|---|
| `guide_fit.py` | 모델이 후보 가이드마다 제품·작업 일치(`match`)를 판정하고 근거 문장(quote)을 인용합니다. 코드가 인용이 가이드 본문에 실제로 있는지 검증하며, 검증에 실패하거나 일치 가이드가 없으면 `no_verified_guide`(그리지 않음)입니다. |
| `consensus.py` | 같은 사진에 대한 N회 영역 제안을 과반(실패 호출 포함)으로 합칩니다. 박스는 좌표별 중앙값이며, 표가 크게 어긋나면(IoU < 0.3) `stable: false`로 표시해 뷰어가 숨기게 합니다. 과반이 없으면 `uncertain`입니다. |

## 워크플로

```
사진 + 등록 기기 + 질문
   └─ 후보 가이드 검색 ─ 적합성 판정(모델) ─ guide_fit.decide(인용 검증)
        ├─ no_verified_guide → 오버레이 숨김, 다시 찍기/문의 안내
        └─ 선택된 가이드 1개 → 영역 제안 N회 → consensus.aggregate
             ├─ uncertain → 오버레이 숨김
             └─ ok → stable 영역만 후보로 표시 (사람 검수 전 영역은 "후보")
```

## 논문(EgoAfford, arXiv 2608.04533)의 GPT-5.x 사용 방식

논문 HTML 본문 §3.2–3.3을 읽고 확인한 내용입니다. GPT-5.5는 **추론 모델이 아니라 데이터 구축(주석) 파이프라인**에 쓰입니다.

| 단계 | 논문의 방식 |
|---|---|
| 과제 생성 | 여러 LLM(GPT 5.5 포함)이 객체·다단계 과제를 생성하고, GPT-Image-2가 단계별 이미지를 생성 |
| 자동 주석 | Grounded-SAM이 객체 박스를 찾고 → **GPT-5.5가 단계의 구성요소(대상/도구/목적지)를 박스에 연결하고 박스 안 기능 부위에 점 프롬프트를 지정** → SAM2가 부위 마스크 생성 |
| 품질 | 사람 검수 전 gIoU 0.696 / cIoU 0.523. 논문은 "사람 검증 없이는 신뢰할 수 없다"고 결론 |

핵심: LLM에게 마스크나 좌표를 직접 그리게 하지 않고, **검출기 박스 중 선택 + 점 하나 지정**만 맡기고 분할은 전용 모델(SAM2)이 합니다. 그래도 정확도가 부족해 사람 검수가 필수였습니다.

### 이 저장소에 반영 가능성 검토

| 항목 | 판단 |
|---|---|
| "LLM은 후보 선택·점 지정, 분할은 전용 모델" 구조 | **반영 가능(설계 수준)**. 영역 제안 단계를 `consensus.aggregate`에 넣는 현재 구조와 맞습니다. 모델이 직접 박스를 그리게 하는 방식보다 안전합니다. |
| LLM 출력은 "초기 제안"으로만 사용 | **이미 부합**: 사람 검수 전 영역은 "후보"로 표시하고, 불확실하면 숨깁니다. |
| 합성 단계 이미지 생성으로 데모·평가 자산 확대 | 가능하나 반드시 "합성" 라벨을 붙여 실제 제품 지원과 분리해야 합니다. 실제 정확도로 보고하지 않습니다. |
| 온디바이스 실시간 오버레이 | **직접 반영 불가**. 논문 파이프라인은 오프라인 주석용이라 프레임 단위 추적에는 쓰이지 않습니다. 추적 오버레이는 기존 네이티브/웹 추적을 유지합니다. |
| SAM2·Grounded-SAM 도입 | 서버 어댑터로만 가능합니다. 모델 가중치·GPU·비용이 필요하고, 유료 리소스 배포는 별도 승인 대상이며 아직 도입하지 않았습니다. |
| EgoLens 모델 / EgoAfford 데이터 | 가용성·라이선스를 확인하지 못했습니다. 책상 위 과제 데이터라 가전 제품 지원 정확도를 보장하지 않습니다. |

다음 단계 후보(미착수): 검출 어댑터가 박스 후보를 주고 모델이 후보 id와 점만 고르는 계약을 `guide_api`에 추가하고, 결과를 `consensus`로 합친 뒤 사람 검수 큐에 넣습니다.

## 범위와 한계

### Foundry 영역 제안 목업 (확인된 것)

- `guide_api/region_proposal.py`: Foundry 비전 모델이 부품별 점·박스를 제안하고, 형식·범위·점-박스 포함 여부를 검증해 통과한 것만 "초안"으로 남깁니다. Entra 토큰만 사용하며 키는 저장소에 없습니다.
- 기존 배포 `brk445demo-01`의 `gpt-5-2`(gpt-5.2)로 합성 에어컨 이미지를 1회 실행해 2/3개 부품 영역을 받았고, 보이지 않는 부품은 제외됐습니다. 정확도는 측정하지 않았습니다(목업 단계). 결과는 사람 검수 전까지 Overlay에 쓰지 않습니다.
- SAM2·Grounded-SAM은 승인은 받았으나 아직 배포하지 않았습니다. 인프라 생성과 유료 배포는 별도 단계로 남아 있습니다.
- 확인한 구독 배포 중 가장 최신은 `gpt-5.4-mini`(`aif-aiops-arb-dev-d7k3`)이며, gpt-6.x는 구독에서 확인되지 않았습니다.

- 위 모듈은 모델 호출을 포함하지 않는 순수 로직이며, 단위 테스트(`server/tests/test_guide_fit_consensus.py`)만 통과했습니다.
- gpt-6.1-terra 등 실제 모델 호출, 실제 가이드·사진 정확도는 측정하지 않았습니다. 인식률이 좋다는 점은 미검증입니다.
- 모델 어댑터(프롬프트·호출)는 아직 연결하지 않았습니다. 연결 시 키는 저장소·APK·로그에 넣지 않고, 카메라 프레임은 연속 업로드하지 않습니다.
- 합성 데모 에셋은 실제 삼성 제품 지원과 분리해 표시합니다.
